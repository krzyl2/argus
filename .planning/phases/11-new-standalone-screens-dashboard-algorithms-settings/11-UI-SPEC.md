# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 10 already locked every token, component, and a11y rule this phase consumes — nothing here
redefines spacing/typography/color primitives. This contract only resolves what is genuinely new
for three screens that didn't exist before: page/section composition, mock-data marking, and two
data-availability conflicts surfaced during research (flagged below, not silently resolved). No
interactive question round was run for pure layout choices (grid columns, card density, copy
wording) — these are decided prescriptively from the reference kits + existing CSS conventions, per
the "decisive, minimal-questions" project profile. Two items ARE flagged as requiring planner/user
confirmation because they touch data availability, not just visuals (see "Flagged Conflicts").

---

## Flagged Conflicts (Rule 7/12 — surfaced, not averaged)

1. **"Active detectors" KPI cannot be computed frontend-only as literally specified.**
   `11-CONTEXT.md` D-01 says the tile = "sum of per-sensor detectors + group count," computed with
   "no new backend." But `GET /api/sensors` (`api/types.ts` `SensorEntry`) does not return a
   per-entity detector list or count — only `isTracked: boolean`. There is no other existing
   endpoint that exposes it (confirmed: `/api/sensors`, `/api/sensors/save` (POST-only),
   `/api/groups`, `/api/groups/save`, `/api/detectors/catalog`, `/api/detectors/defaults`,
   `/api/groups/{id}/status` — none carry per-sensor detector counts).
   **Recommendation (decide now, don't re-ask):** add one additive field to the *existing*
   `GET /api/sensors` response — `detectorCount: number` per entry (0 for untracked) — computed
   server-side from the same `EntitiesConfig`/`ILiveEntitiesConfig` data `IsTracked` already reads.
   This is NOT a new route/endpoint (D-01's actual constraint, read narrowly), just one more field
   on the response Program.cs already builds — same category of change as D-06's Settings addition,
   smaller. Dashboard then computes `activeDetectors = sum(detectorCount for tracked) + groups.length`.
   If the planner/user rejects even this narrow addition, the fallback is to rename the tile
   **"Active group detectors"** and show `groups.length` only — never silently show a wrong number
   under the original label.
2. **"Log level" in Settings → Batch & detection has no backing field today.** `ConnectionSettings.cs`
   has no `LogLevel` property; ASP.NET Core's own `Logging:LogLevel:Default` config key is a
   different surface (`IConfiguration`, not `ConnectionSettings`). Planner must confirm at plan-time
   whether `GET /api/settings` reads `IConfiguration["Logging:LogLevel:Default"]` directly (cheap,
   recommended) or the Log level field is dropped from this phase's Settings screen. Do not
   hardcode/guess a log level client-side.

## Typography

No new sizes/weights. Reuses the Phase 10 locked 8-size scale (`micro` 11px … `kpi` 34px, only two
weights: 400/600) verbatim — see `10-UI-SPEC.md`. Roles this phase actually uses:

| Role | Size token | Weight | Line Height | Usage |
|------|-----------|--------|-------------|-------|
| Page title | `title` (24px) | 600 | 1.2 | `<h1>` on all 3 screens |
| Page subtitle | `lead` (16px) | 400 | 1.5 | Under the title, secondary color, max-width ~620px |
| Section label | `label` (12px) | 600 | 1.4, uppercase, `--letter-spacing-caps` | "Recent anomalies", "System health", "Connections", "Batch & detection", "Appearance", "Presets" — new `.argus-section-label` CSS class (recipe identical to `.argus-kpi-tile__label`, generalized) |
| KPI value | `kpi` (34px) | 600 | 1, tabular-nums | KpiTile values only |
| Body | `body` (14px) | 400 | 1.5 | Best-for copy, card body text |
| Body mono | `body` (14px) | 400/600 | 1.5 | Detector/entity/group identifiers |
| Label / meta | `label` (12px) | 600 | 1.4 | Row secondary lines, param-schema descriptions, field captions |

No arbitrary sizes outside this scale (the reference kits use ad-hoc 11px/13px in a few places —
snap those to `label`/`body` per this table, do not introduce new pixel values).

## Screen Specifications

### 1. Dashboard (`#/dashboard`)

**Layout:** `.argus-page-header` (title + subtitle) → new `.argus-dashboard-kpi-row` (CSS grid,
`grid-template-columns: repeat(4, 1fr)`, gap `--space-md`, margin-bottom `--space-xl`; responsive:
`<900px` viewport width → `repeat(2, 1fr)`; `<560px` → `repeat(1, 1fr)`, mirroring the existing
`.argus-filters`/`.argus-param-grid` breakpoint convention) → new `.argus-dashboard-layout` (CSS
grid, `grid-template-columns: 1.4fr 1fr`, gap `--space-lg`, `align-items: start`; single column
below 900px) containing "Recent anomalies" (left) and "System health" (right).

**KPI tiles (exactly 4, in this order):**

1. `KpiTile label="Monitored sensors" value={tracked.length} accent` — real, from `GET /api/sensors` (`entries.filter(e => e.isTracked).length`)
2. `KpiTile label="Groups" value={groups.length}` — real, from `GET /api/groups`
3. `KpiTile label="Active detectors" value={activeDetectors} hint="across sensors + groups"` — real, **pending the Flagged Conflict #1 resolution** above
4. `KpiTile label="Home Assistant" value="Connected" hint="mocked — no endpoint yet"` — mock+TODO (D-01); do **not** pass a `status` prop (a StatusDot here would visually claim a live/verified state that doesn't exist)

**Recent anomalies (mock+TODO, D-02):** `.argus-section-label` "Recent anomalies" → `Banner
tone="info"` mock marker (see Copywriting) → `Card padding="none"` containing one row per mock
anomaly: `StatusDot` (severity→status mapping above) + entity/group identifier (mono, `body`,
truncated with ellipsis) + secondary line ("sensor"/"group" · detector name · relative time, `label`
size, secondary color) + `Badge` with the score (2 decimals, tone `error`/`warn`/`neutral` for
high/med/low). Row divider: `1px solid var(--color-border)`, no divider after the last row. Use this
exact mock dataset (from `Argus Design System/ui_kits/admin/data.js`, already grounded in real
product identifiers):

```
{ entity: null, group: 'Klimat salonu', score: 0.74, severity: 'med', when: '18 min ago', detector: 'copod' }

{ entity: null, group: 'Temperatury pokoi', score: 0.49, severity: 'low', when: '5 hr ago', detector: 'peer_divergence' }
```

**System health (mock+TODO, D-03):** `.argus-section-label` "System health" → `Banner tone="info"`
mock marker → `Card padding="sm"` containing one row per mock health item: `StatusDot` (no `pulse` —

### 2. Algorithms (`#/algorithms`)

**Layout:** `.argus-page-header` → grid `repeat(auto-fill, minmax(280px, 1fr))`, gap `--space-md`
(same recipe as the existing `.argus-algorithm-chooser__grid`) — one `Card padding="sm"` per entry
from `GET /api/detectors/catalog` (5 cards: peer_divergence, ecod, copod, pca, iforest, in that
catalog order — never reordered/filtered client-side).

**Per-card composition (read-only, no `SensitivityPreset`/`Input` editing controls — D-04):**

- Name: `entry.name` verbatim, mono, `lead` size, weight 600
- Best-for: `entry.bestFor` verbatim (never hardcoded/paraphrased client-side — Phase 9's own
  anti-pattern lesson), `body` size, secondary color, `line-height: 1.5`
- Presets row: `.argus-label` caption "Presets" then one `Badge tone="neutral"` per preset in
  `entry.presets`, content = `"{preset.label}: {params joined as key=value, comma-separated, in
  entry.paramSchema key order}"` (e.g. `"Med: threshold=3.5"`, `"High: contamination=0.2,
  n_estimators=150"`) — flex row, `gap: var(--space-sm)`, `flex-wrap: wrap`
- Param schema: `Disclosure summary="Parameter schema"` containing one new `.argus-catalog-param-row`
  per `entry.paramSchema` item (new CSS class: flex row, `justify-content: space-between`) — key
  (mono, `body`) left, description (`label`, secondary) right, formatted
  `"{type} · {min}–{max} · step {step}"` (e.g. `"number · 0.01–0.5 · step 0.01"`)

No `SaveBar`, no "Single sensors" section (both explicitly rejected, D-04/D-05).

### 3. Settings (`#/settings`)

**Layout:** `.argus-page-header` → three stacked sections, `max-width: 720px`, `gap: var(--space-lg)`
between sections (D-08 — all 3 sections from the reference kit, in this order):

1. **Connections** (read-only) — `.argus-section-label` "Connections" → `Card padding="sm"`:
   - Caption row: "Home Assistant & MQTT are injected automatically by the Supervisor." (`label`,
     secondary) + `Badge tone="ok"` "auto" — **do not display HA URL/MQTT host/token fields**; D-07's
     exposed-field list intentionally excludes them (Supervisor-managed, out of this screen's scope)
   - `Input value={detectorEndpoint} disabled ariaLabel="Detector gRPC endpoint (mTLS)"` (mono) with
     visible field label "Detector gRPC endpoint (mTLS)" above it (reuse the existing
     `.argus-param-field__label` pattern for the visible label — `Input` itself has no built-in
     label slot)
   - Two-column row (`grid-template-columns: 1fr 1fr`, gap `--space-md`, same recipe as
     `.argus-param-grid`): "InfluxDB URL (optional)" / "InfluxDB bucket", both disabled mono `Input`s

2. **Batch & detection** (read-only) — `.argus-section-label` "Batch & detection" → `Card
   padding="sm"`:
   - Two-column row: "Batch interval (minutes)" (disabled `Input type="number"`, unit suffix "min")
     / "Nightly fit hour (UTC)" (disabled `Input type="number"`, unit suffix "h")
   - "Log level" (disabled `Select`, options `debug`/`info`/`warning`) — **see Flagged Conflict #2**;
     if the planner drops this field for Phase 11, drop the whole row, don't render an empty/broken
     control

3. **Appearance** (the one functional section, D-09) — `.argus-section-label` "Appearance" → `Card
   padding="sm"`:
   - "Theme" caption (`.argus-label`)
   - A 2-option Light/Dark radio group, reusing the **existing** `.argus-sensitivity-preset-picker`
     family CSS classes directly in plain JSX (`__options`/`__option`) — do **not** repurpose the
     typed `SensitivityPresetPicker.tsx` component, which is hardwired to `DetectorCatalogEntry` and
     is not a generic 2-option control. No "System" option (D-09 — Light/Dark only).
   - Current selection reads `data-theme` off `<html>`; on change, writes `localStorage('argus-theme')`
     + sets `data-theme` — **identical mechanism to `Sidebar.tsx`'s toggle**, no new theme logic (D-09)

**Required refactor note (interaction contract, not just visual):** `Sidebar.tsx` currently holds
theme as local `useState`. With two live surfaces (Sidebar toggle + Settings radio group) both
reading and writing the same `localStorage`/`data-theme` state, local component state will go stale
if the *other* surface changes it while both are mounted — the Sidebar's icon/label wouldn't update
after a Settings-page toggle. Extract the theme read/write into one shared reactive source (e.g. a
`theme` `@preact/signals` signal in a small new `state/theme.ts`, mirroring the existing
`route`/`draftParams` signal pattern) that both `Sidebar.tsx` and the new Settings page subscribe to
— this is a small, surgical change (Rule 3), not a new abstraction layer, and only justified because
it now has 2 real call sites (not speculative).

**No SaveBar** — Appearance changes apply immediately (same as the Sidebar toggle today), matching
D-09's "no new theme logic."

## API Contract (new/changed only)

- `GET /api/sensors` — **if Flagged Conflict #1 is accepted**, add `detectorCount: number` per
  `SensorEntry` (0 when untracked). Otherwise unchanged.
- `GET /api/groups`, `GET /api/detectors/catalog` — consumed as-is, no changes (existing types in
  `api/types.ts` are authoritative).
- `GET /api/settings` (new, D-06) — must follow the `IsAuthorizedRequest(req.HttpContext)` guard
  pattern used by every other `/api/*` route (`Program.cs`). Add a matching TS type to
  `api/types.ts`:

```ts
export interface SettingsResponse {
  detectorEndpoint: string | null;
  influxUrl: string | null;
  influxBucket: string | null;
  batchIntervalMinutes: number;
  nightlyFitHour: number;
  logLevel: string | null; // see Flagged Conflict #2 — source TBD
}
```

  Must never include `HaToken`, `MqttPassword`, `MqttUser`, `TlsCa`/`TlsCert`/`TlsKey` contents, or
  `InfluxToken` (D-07 secret redaction — read `ConnectionSettings.cs` field-by-field, do not
  serialize the whole object).

## Navigation (D-10)

`Sidebar.tsx` `NAV_ITEMS`: flip `dashboard`/`algorithms`/`settings` from `disabled: true` to real
`href`s (`#/dashboard`, `#/algorithms`, `#/settings`); extend `isActive()` with the 3 matching exact
routes. `router.ts`: add 3 static routes (no `:id` segments, no router library — unchanged pattern).
Default route stays `#/sensors` (D-10, unchanged).
