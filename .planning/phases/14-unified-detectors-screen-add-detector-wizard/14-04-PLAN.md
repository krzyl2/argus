<objective>
Assemble the user-facing unified Detectors screen and wire the new routes. `DetectorsPage` loads both
data sources and renders a `DetectorList` of `DetectorListRow`s — one row per group or tracked sensor,
each row navigating (only) to its editor. `main.tsx` grows three route branches and repoints its
fallback from SensorsPage to DetectorsPage. This is the Wave 2 integration plan: it consumes
`detectorRows` + `routeSensorEntityId` (14-01) and imports `AddDetectorWizard` + `SingleDetectorEditorForm`
(14-02), so it must run after both.

Purpose: Deliver DET-01/DET-02/DET-03 (the unified list + navigation to the two editors) and complete
DET-05's route table so the new IA is reachable end-to-end.

Output: New `DetectorsPage.tsx`, `DetectorList.tsx`, `DetectorListRow.tsx` (+ tests) and a modified
`main.tsx` route switch.
</objective>

## Artifacts this phase produces

- `DetectorsPage.tsx` (new) — `/detectors` list screen: mount-loads `loadGroups()` + `loadSensors('')`, renders a DS page header, an "Add detector" primary link to `#/detectors/add`, and `<DetectorList rows={detectorRows.value} />`.
- `DetectorList.tsx` (new) — Card-wrapped `<ul class="argus-list">` mapping `DetectorRow[]` to `DetectorListRow`, with a custom `.argus-empty` branch for zero rows.
- `DetectorListRow.tsx` (new) — dispatches on `row.kind`: a group variant (relocated `GroupListRow` look: friendlyName/groupId title, mode + detector badges, member count, Edit link to `#/groups/:id`) and a sensor variant (entityId title + optional friendly name, tracked badge + assigned-detector badge, Edit link to `#/detectors/sensor/:id`). Rows only navigate — no checkbox, no inline disclosure, no untrack/delete.
- `main.tsx` — route switch gains `/detectors/add`, `/detectors/sensor/*`, `/detectors` branches; fallback → DetectorsPage; SensorsPage import removed.
