<objective>
Re-home the Pattern Filters (include/exclude auto-track) UI. Once the Sensors nav item is removed
(14-01), the only screen that rendered `PatternFiltersPanel` disappears — leaving the feature working
server-side but invisible/uneditable (Pitfall 4). Relocate its rendering into the Settings screen
(D-08b), with a Save bar, and — critically — a D-07 full-set mount guard, because the pattern-filter
save reuses the very same sensors full-list-replace `save()`.

Purpose: Prevent silent feature loss and, more importantly, prevent a Settings save from truncating
`entities.yaml`. This plan has no dependency on the other Wave 1 plans (independent file), so it runs
in parallel.

Output: Modified `SettingsPage.tsx` with a new Pattern Filters section + save + D-07 guard, and a test.
</objective>

- `SettingsPage.tsx` — a new "Auto-track patterns" section rendering `PatternFiltersPanel` bound to `includePatterns`/`excludePatterns` (from `state/sensors`), a `SaveBar` + `SaveResultBanner` wired to `state/sensors` `save()`/`saveState`, and a `loadSensors('')` mount effect (D-07). Existing Connections/Batch/Appearance sections untouched.
- `SettingsPage.test.tsx` (new) — asserts the pattern section renders, the mount loads the full sensor set, and (regression) a save preserves the full tracked set.
