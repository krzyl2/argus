<objective>
Close blocker gap G-14-1 (silent data loss). Two orthogonal, code-proven root causes are
fixed together:

1. WRITE path — POST /api/sensors/save rebuilds the entities.yaml root dict without a groups:
   key, so every sensor save destroys all operator-defined groups on disk and in live config.
2. READ path — GET /api/sensors sources isTracked from the HA registry snapshot, which only
   refreshes on an HA WebSocket reconnect. liveCfg.Swap does not reconcile it, so a just-saved
   sensor reads isTracked=false after a page refresh.

Purpose: A single-sensor detector save must persist the sensor as a tracked row on /detectors
across refresh AND must not wipe existing groups. This unblocks the unified Detectors list
(DET-01/02/03) whose group-row + sensor-row consistency was destroyed by the bug.

Output: Two symmetric fixes in Program.cs, a small config-sourced tracking helper, and two
regression tests that fail on the current code and pass after the fix.
</objective>
