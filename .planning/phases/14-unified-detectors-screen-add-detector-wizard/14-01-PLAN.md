<objective>
Establish the client-only navigation + data plumbing that every Phase 14 screen builds on:
repoint the hash router's default route to `/detectors`, add legacy redirects for the two removed
bare routes, add a new `/detectors/sensor/:entityId` parser, restructure the sidebar nav, and add a
thin computed signal that merges groups + tracked single sensors into one unified row list.

Purpose: Wave 2's Detectors screen and route wiring (14-04) import `routeSensorEntityId`,
`detectorRows`, and the restructured nav from this plan. Getting the router/redirect/merge contracts
right first lets the screen work be pure rendering.

Output: Modified `router.ts` (D-01) + `Sidebar.tsx` (D-02/D-04), new `state/detectors.ts` (D-03),
and three test files proving the redirect, parse, nav, and merge behaviors.
</objective>

## Artifacts this phase produces

- `router.ts` — new default route `/detectors`; `redirectLegacyRoutes` behavior folded into `normalizeHash`; new `parseSensorEntityId(path)` function; new `routeSensorEntityId` signal (updated in the existing `hashchange` listener); boot `effect` retargeted to `#/detectors`. `parseGroupId` and `routeGroupId` remain byte-identical.
- `state/detectors.ts` — `DetectorRow` interface (`key`, `kind: 'group' | 'sensor'`, optional `group?: GroupConfig`, `entry?: SensorEntry`) and the `detectorRows` computed signal.

- `Sidebar.tsx` — `NAV_ITEMS` and `isActive` restructured (Sensors/Groups removed; Detectors + Add detector added).

<assumption_delta_decision>
This phase generalizes two previously-separate nouns — a "group" and a "tracked sensor" — into one
unified "detector" row. The now-primary noun is the unified detector-row (`DetectorRow`). Decision:
**add-alongside via a discriminated union** (`kind: 'group' | 'sensor'` with two thin variant payloads
under one list) rather than collapsing both into a single flattened shape. Accepted because group rows
and sensor rows carry genuinely different meta and actions (mode/detector badges + group-editor link
vs. tracked badge + single-sensor-editor link), and namespaced keys (`group:` / `sensor:`) prevent any
future identity collision. Rationale is one line; advisory, non-blocking.
</assumption_delta_decision>
