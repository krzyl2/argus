# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Every value below is pre-populated from `Argus Design System/` (the phase's own canonical
reference package, per `10-CONTEXT.md`) and `orchestrator/ui/public/css/argus.css` (the existing
production token file being extended, not replaced). Nothing in this contract required a new
user decision — the design system package IS the locked visual spec; this file translates it into
the design-contract shape the planner/executor/checker expect. Where the system's scale exceeds
this template's default guidance (e.g. more than 4 type sizes), that is flagged explicitly as an
intentional carry-over from the already-locked source, not scope creep (Rule 7).

## Typography

Base template roles, mapped to the system's scale:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.15 |

**Only two weights exist in the whole system: 400 (regular) and 600 (semibold).** Never introduce a
third weight.

**Flagged carry-over (Rule 7 — not re-litigated, inherited from the locked source):** the actual
type scale in `Argus Design System/tokens/typography.css` has 8 sizes, not the template's default
3-4 — this is the existing, already-shipped/locked scale (`argus.css` already has 4 of these; the
Design System package adds 4 more for the new screens). Declare all 8; do not prune to fit the
generic guidance:

| Size token | Value | Usage |
|------------|-------|-------|
| micro | 11px | Dense captions, table meta |
| label | 12px | Field labels, secondary row text, pills |
| body | 14px | Default body copy, inputs, buttons |
| lead | 16px | Section intro copy |
| heading | 20px | Sub-section headings |
| title | 24px | Page titles |
| display | 28px | Hero/large numeric or emphasis |
| kpi | 34px | Dashboard KPI tile numbers only |

Letter-spacing: `0.04em` on uppercase eyebrow/section labels only (`--letter-spacing-caps`).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Save" (existing dominant CTA, `SaveBar`/`GroupEditorForm`) — Phase 10 does not introduce new CTAs, it retrofits the shared `Button` component these already use |
| Empty state heading | "No sensors tracked yet" (per `EmptyState.prompt.md` reference example — reuse pattern for any other empty list surfaced during retrofit) |
| Empty state body | "Tick a sensor above to start monitoring it." — imperative, second-person, states the next concrete action, per readme.md voice rules |
| Error state | Per-field inline: existing `.argus-param-field__error-msg` convention (message under the offending field) + banner rollup: "3 fields need attention." (tone `validation`) — problem count + implicit fix-path (scroll to highlighted fields). Do not invent new copy patterns; Phase 10 must preserve these verbatim during the Button/Banner retrofit |
| Destructive confirmation | Two-step inline arm/confirm on the same button, **not** `window.confirm()`: first click → button label becomes "Confirm delete" (armed state, ~3s timeout auto-reverts if not clicked again); second click within the window executes. This is an existing locked pattern (see `GroupListRow.tsx` "Delete group" → "Confirm delete", sourced from the prior Phase 8 UI-SPEC) — the Phase 10 `Button` component (variant `destructive-ghost`) must support this arm/confirm label swap, not replace it with a modal |

Voice rules (readme.md, apply to all new/retrofitted copy in this phase): terse, factual,
operator-facing, second-person imperative for instructions. No marketing tone, no emoji. Entity
friendly-names stay Polish (`Salon temperatura`); all UI chrome and entity IDs stay English/monospace.
Numbers carry trailing units (`21.4 °C`, `0.82` for scores — two decimals). "Argus" referred to by
name, never "we"/"the app".

## Cross-Cutting A11y Rules (this phase's two required rules)

1. **Focus always visible (A11Y-01):** `:focus-visible { outline: 2px solid var(--color-accent); outline-offset: 2px; }` already exists globally in `argus.css` (line 75-78) — verify no new/retrofitted component (Button variants, radio-cards, Sidebar nav links, Select/Input) overrides or suppresses this with `outline: none` without an equivalent replacement. Do not rebuild from zero; audit and preserve.
2. **Radio-card selection never color-alone (A11Y-02):** AlgorithmCard and SensitivityPreset selected state = `border: 2px solid var(--color-accent)` (`--border-width-strong` token) on top of the existing 1px `--color-border`, i.e. the border must visibly thicken, not just recolor. Applies to every present and future radio-card-style selector in the app (Sensors' detector picker in Phase 12 inherits this from the shared component built here).

## Dark Mode Activation (Claude's Discretion — resolved, locked per 10-CONTEXT.md)

- Replace the existing `@media (prefers-color-scheme: dark)` block in `argus.css` with a
  `[data-theme="dark"]` attribute block — port the fuller token set from
  `Argus Design System/tokens/colors.css` verbatim (names match 1:1; adds `--color-brand-navy`,
  `--color-brand-navy-2`, `--color-on-brand`, `--color-status-warn`, `*-soft` tint variants,
  `--color-row-hover`, `--color-accent-hover` not in the current media-query block).
  Also port `tokens/typography.css`, `tokens/spacing.css`, `tokens/elevation.css` (radius, border,
  control-height, sidebar-width, content-max, shadow tokens) — none of these currently exist in
  `argus.css` outside the color/spacing/typography subset already there.
- Bootstrap (in `orchestrator/ui/src/main.tsx`, before first paint): if no `localStorage` theme key
  exists, read `matchMedia('(prefers-color-scheme: dark)')` once and set `data-theme` on `<html>`
  accordingly. An explicit toggle (Sidebar, THEME-02) always writes `localStorage` and wins from
  then on. The old media-query block is removed outright — no parallel source of truth for the
  same tokens.
