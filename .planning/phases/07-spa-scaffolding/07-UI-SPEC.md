# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Phase Type: Parity Migration (not a design phase)

This phase rebuilds the existing v3.0 server-rendered (htmx) Ingress config UI on a Preact + Vite SPA
foundation with **zero intentional visual redesign**. `argus.css` (already committed at
`orchestrator/Argus.Orchestrator/wwwroot/css/argus.css`) is carried forward verbatim as the global
stylesheet and is the **visual source of truth** for this phase. Do not introduce new colors, spacing
values, font sizes, or component patterns not already present in that file. New feature UI (group
config, algorithm chooser, friendly-name search) is Phase 8 — explicitly out of scope here.

Stack is locked in `07-CONTEXT.md` (not re-litigated here): Preact + Vite + TypeScript, Preact hooks +
`@preact/signals`, hash routing (`#/sensors`), relative Vite `base: './'`. No shadcn/ui — this is not a
React/Next.js component-library project; `argus.css` is a hand-authored CSS custom-property system, and
CONTEXT.md already locked "carry it forward" as the styling decision. shadcn init is therefore skipped
(not applicable to this stack/decision).

## Color

Source: `argus.css` `:root` (light) + `@media (prefers-color-scheme: dark)` override — already implements 60/30/10 via existing tokens. Preserve both blocks unchanged.

| Role | Value (light / dark) | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface` `#f8f9fb` / `#1c1c1e` | Page background, filter textarea background |
| Secondary (30%) | `--color-element` `#ffffff` / `#2c2c2e` | Header, footer, list, cards, inputs, detector entry panels |
| Accent (10%) | `--color-accent` `#0d6efd` / `#3b9eff` | Primary save button, focus rings, links, checkbox/radio accent-color, "Add detector" ghost button, search/input focus border |
| Destructive | `--color-destructive` `#dc3545` / `#ff453a` | "Remove detector" ghost button only |
| Status OK | `--color-status-ok` `#198754` / `#32d74b` | "tracked" pill, success save banner |

Accent reserved for: primary CTA button (`.argus-btn--primary`), focus-visible outline, links, checkbox

No new semantic color is needed — `--color-destructive` already exists and is reused for status-error;
this phase introduces no new destructive action beyond "Remove detector" (already present in v3.0).

### Client-side field validation rules (ports `_validationScript` from `EntityPickerPage.cs`)

Reproduce exactly — these are the parity spec, not a redesign opportunity:

| Field key | Rule | Error message |
|---|---|---|
| `window`, `n_trees`, `min_consecutive`, `frozen_window` | integer, ≥ 1 (`window`/`n_trees` ≥1; `min_consecutive`/`frozen_window` ≥1) | "Must be a whole number ≥ 1." |
| `period` | integer, ≥ 2 | "Must be a whole number ≥ 2." |
| `high_threshold` | float, 0 < v ≤ 1, must be > `low_threshold` | "Must be between 0 and 1, and greater than low threshold." |
| `low_threshold` | float, 0 ≤ v < 1, must be < `high_threshold` | "Must be between 0 and 1, and less than high threshold." |
| `frozen_variance_threshold` | float, ≥ 0 | "Must be 0 or greater." |
| `threshold` (MAD/STL) | float, > 0 | "Must be greater than 0." |
| any empty/non-numeric | — | "Must provide a value." |

Save button (`.argus-btn--primary`) is `disabled` whenever ≥1 field is in `.argus-param-field--error`
state — exact parity with the existing `usb()` function.

## States (loading / empty / error) — sensor list & save flow

| State | Trigger | UI | Copy source |
|---|---|---|---|
| Loading (initial) | SPA mount, `GET /api/sensors` in flight | Reuse `#argus-spinner` visual (`.argus-list` area can show it, or a lightweight skeleton — no spinner text needed, spinner is icon-only per existing pattern) | n/a (visual only) |
| Loaded — has results | `GET /api/sensors` returns ≥1 entry | `SensorList` renders rows | n/a |
| Empty — no query | Registry has 0 sensors, `q` empty | `EmptyState` (no-query variant) | "No sensors found." / "Argus has not yet received a sensor snapshot from Home Assistant. Check that the add-on can reach the Supervisor and that the detector is running." |
| Empty — search miss | `q` non-empty, 0 matches | `EmptyState` (query variant) | `No sensors match "{q}".` / "Try a different search term or clear the filter." |
| Saving (in flight) | POST `/api/sensors/save` in flight | Spinner visible (`#argus-spinner`), save button `disabled` | n/a |
| Save success | 200 + entity count | `.argus-banner--success` | `Saved — pipeline active. {count} {entity|entities} tracked.` + optional HST warm-up note (see Copywriting Contract) |
| Save reloading (intermediate, if surfaced) | optimistic intermediate state | `.argus-banner--reloading` | `Saved — pipeline reloading… ({count} {entity|entities})` |
| Save validation blocked | client OR server validation fails | `.argus-banner--validation` | `Save blocked: {errorCount} field(s) have invalid values. Correct the highlighted fields and try again.` |
| Save error (network/server) | non-2xx or fetch throw | `.argus-banner--error` | `Save failed. {reason}. Check the add-on log for details.` — reason is a generic string from server (`"disk error"` / `"unexpected error"`), never raw exception text |
| Field-level validation error | one param field fails a rule | `.argus-param-field--error` + inline `.argus-param-field__error-msg` | See validation rules table above |

All banner/empty-state copy must be reproduced **verbatim** from `EntityPickerPage.cs` (English —
these are operator-facing UI strings in the existing English UI; do not translate, do not reword).

## API Contract (JSON — converts existing htmx-fragment endpoints)

Per `07-CONTEXT.md` UI-03/04 decisions, endpoints return JSON instead of HTML fragments. Shape is
informed directly by `EntityPickerPage.BuildDetectorEntry`'s data inputs and `EntitiesConfig`/
`DetectorConfig` models — this is a wire-format contract, not new product surface.

| Endpoint | Method | Response shape (informative, planner/executor finalize exact schema) |
|---|---|---|
| `/api/sensors?q=` | GET | `{ entries: [{ entityId, friendlyName, currentValue, unitOfMeasurement, isTracked }] }` |
| `/api/sensors/save` | POST (JSON body, not form-encoded) | `{ ok: true, count, hasHst }` on success; `{ ok: false, kind: "validation", errorCount }` or `{ ok: false, kind: "error", reason }` on failure — `kind` lets the SPA pick the correct banner variant without string-sniffing |
| `/api/detectors/defaults?name=hst|mad|stl` | GET (replaces `/api/detectors/new-entry` fragment) | `{ name, params: { ...defaults } }` — same default-values table above; SPA can also hardcode this table client-side per the `AddDetectorButton` note, but the endpoint should still exist/match if the executor chooses server-driven defaults for single-source-of-truth |

Auth: unchanged — `IsAuthorizedRequest` (Supervisor IP 172.30.32.2 / loopback / dev bypass) continues
to gate every `/api/*` route. No new auth surface introduced in this phase (full `validate_session` is
explicitly out of scope per CONTEXT.md deferred list).
